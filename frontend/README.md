# Histeria Workspace

Тёмная веб-панель управления аккаунтами на React + TypeScript, Ant Design и Tailwind CSS. Сборка — Vite. Интерфейс на русском языке, адаптируется к мобильному экрану.

## Запуск

```bash
npm install
npm run dev
```

Адрес выводится в терминале (по умолчанию `http://localhost:5173`).

```bash
npm run build # TypeScript и production-сборка
npm run lint  # ESLint
npm run preview # просмотр production-сборки
```

## Возможности

- Вход в панель с Django session cookie.
- «Реакции»: постановка выбранного emoji от всех или выбранных готовых аккаунтов на сообщение по ссылке. Поддерживаются публичные и приватные ссылки t.me, а также сообщения в темах. Проверка сообщения и разрешений, фрагмент в предпросмотре, подтверждение, прогресс и результат каждого аккаунта. При ошибке аккаунт пропускается, остальные продолжают; неизвестные попытки не повторяются. Аккаунтам нужен доступ к чату.
- «В личку»: массовая отправка одного текста от всех или выбранных готовых аккаунтов каждому указанному пользователю. Получатели — @username, прямая ссылка t.me или телефон с кодом страны (если поиск разрешён получателем). Предпросмотр, подтверждение, прогресс, остановка после текущего сообщения и результаты каждой отправки работают как у комментариев. При ошибке, включая FloodWait и таймаут, аккаунт и его оставшиеся отправки пропускаются; другие отправители продолжают. Смена Telegram ID получателя останавливает очередь; неизвестный результат не повторяется автоматически.
- Блок «Здоровье аккаунтов»: отдельные проверки сессии и спамблока через официальный @SpamBot для всех или выбранных аккаунтов, прогресс и остановка после текущего. Статусы и время проверки видны в таблице; ответ бота и ошибки — в карточке аккаунта. Неизвестный ответ бота показывает «Не определено», сетевой сбой отличается от недействительной сессии. Результаты хранятся на сервере.
- «Прогреть аккаунты»: обмен личными сообщениями между выбранными аккаунтами на протяжении 24 часов, отдельный случайный интервал 40–80 минут для каждого отправителя, редактируемые тексты, журнал и остановка. При ошибке очередь переходит к следующему аккаунту, повторная отправка учитывает FloodWait. Панель показывает счётчики и последнюю ошибку каждого участника. Фоновый исполнитель включается вместе с Django runserver; для WSGI/ASGI нужен `manage.py run_warmups`.
- Подключение настоящих Telegram-аккаунтов по телефону, коду и 2FA.
- Редактирование имени, фамилии, username, описания и аватарки прямо в карточке.
- Случайные имена, username, короткие описания и абстрактные JPEG-аватарки без внешнего сервиса.
- «Сгенерировать всем» / «Сгенерировать выбранным»: предпросмотр, выбор полей, последовательное применение, результаты и остановка после текущего аккаунта.
- Серверное хранение аккаунтов и журнала; зашифрованные Telegram-сессии и API-ключи.
- Настоящая проверка подключения к Telegram, поиск, фильтры, группы, экспорт и адаптивная таблица.
- «Сообщения / комментарии»: публикация от всех или выбранных готовых аккаунтов в свои чаты/каналы и комментарии к своим постам. Проверка владельца канала и группы обсуждения, предпросмотр, подтверждение, результаты каждого отправителя и остановка после текущего запроса. Отправителям нужны соответствующие права Telegram; вкладка должна оставаться открытой до завершения.
- «Массовый репорт» в шапке списка аккаунтов: форма с выбором аккаунтов, цели, причины, пояснения и периода (по умолчанию 60 минут). Черновик можно сохранить в localStorage этого браузера, отдельно для каждого пользователя панели, в том числе при неполном заполнении. При повторном открытии поля восстанавливаются, недоступные аккаунты исключаются, подтверждение сбрасывается. Выбранные в таблице готовые аккаунты подставляются, если сохранённого черновика нет. Основная кнопка активируется после заполнения всех полей и подтверждения данных, сохраняет черновик и сообщает, что отправка не подключена. Форма не создаёт задач и не выполняет запросы к API.
- Локальные настройки внешнего вида и черновики режимов.

Нужен Django backend на 127.0.0.1:8000: запросы /api проксируются через Vite. Инструкция запуска, создания пользователя и настройки Telegram — в [backend/README.md](../backend/README.md).
Первый вход в панель использует логин и пароль Django. Затем укажи API ID / API Hash в настройках и подключи аккаунт. Демо-аккаунты и имитация выполнения удалены. Массовые сообщения, комментарии, реакции и подписки доступны через кнопки над таблицей. Автоматические сценарии подписок в редакторе конфигурации и Mini Apps пока не запускаются.

Кнопка «Подписаться» открывает массовую подписку от всех или выбранных готовых аккаунтов на 1–10 каналов. Поддерживаются username, публичные и пригласительные ссылки. Предпросмотр не вступает в канал; действие начинается после подтверждения. Для каждого аккаунта отображается результат: подписан, уже подписан, заявка на одобрение, ошибка или неизвестный результат. При ошибке аккаунт и его оставшиеся действия пропускаются, остальные продолжают. Платные подписки не поддерживаются; повторов при неизвестном результате нет. Можно остановиться после текущего действия. Оставь вкладку открытой до завершения.

## Структура

```text
src/
  components/
    UI/             переиспользуемые кнопки, поля, меню, карточки и индикаторы
    accounts/       таблица, вход Telegram, редактор профиля и генератор
    auth/           вход в панель
    activity/       журнал и элементы событий
    common/         элементы с общей логикой предметной области
    config/         редакторы текста, реакций, площадок и сценариев
    dashboard/      блоки главной страницы и сборка диалогов
    layout/         меню, верхняя панель, заголовок и подвал
    settings/       настройки пространства
    tasks/          строки задач, действия, выбор аккаунтов и форма запуска
  config/           тема Ant Design
  hooks/            состояние панели, фильтрация и localStorage
  pages/            сборка страницы из готовых блоков
  providers/        контекст приложения и тема
  services/         запросы к Django API
  utils/            общие функции и локальная генерация профилей
  App.tsx           сборка провайдеров и страницы
  data.ts           начальная конфигурация и подписи
  types.ts          типы аккаунтов, конфигурации, задач и событий
  App.css           оформление и адаптивная вёрстка
  index.css         Tailwind и базовые стили
```

Redux Toolkit не требуется для текущего объёма состояния. Серверный API подключён через services. Реальное выполнение Telegram-задач и автоматизацию Mini App следует реализовывать в серверных обработчиках, отдельно от интерфейса.

## Правила сборки интерфейса

- `components/UI` содержит элементы без привязки к аккаунтам и Telegram. Они получают данные и обработчики через props. Базовые контролы используют Ant Design; общие элементы экспортируются из `components/UI/index.ts`.
- Компоненты разделов собирают интерфейс из `UI`: например, таблица использует отдельные ячейки, фильтры и меню действий, а настройки режимов — отдельные редакторы.
- `DashboardPage` соединяет блоки страницы с состоянием из `useDashboard`. Загрузка данных и обработчики находятся в hooks, а тема — в `config/theme.ts`.
- Новый повторяющийся элемент добавляется в `UI` и используется в нужных блоках. Элемент с логикой аккаунтов или задач размещается в соответствующем разделе.
