# HisteriaFarm — Django backend

Django 5.2 + Telethon. Настоящий вход по телефону, коду Telegram и 2FA; чтение и обновление имени, фамилии, username, описания и аватарки. Внешние режимы комментариев, подписок, реакций и Mini Apps пока не реализованы.

## Запуск

Из корня проекта:

```bash
cd backend
python3 -m venv .venv
.venv/bin/pip install -r requirements.txt
cp .env.example .env
.venv/bin/python manage.py migrate
.venv/bin/python manage.py createsuperuser
.venv/bin/python manage.py runserver 127.0.0.1:8000
```

В другом терминале:

```bash
cd frontend
npm install
npm run dev
```

Войди в панель логином пользователя Django. В настройках введи API ID и API Hash своего приложения с https://my.telegram.org/apps. Либо задай TELEGRAM_API_ID / TELEGRAM_API_HASH в backend/.env и перезапусти сервер. Затем нажми «Добавить аккаунт». Код может прийти в приложение Telegram; способ доставки определяет Telegram, SMS не гарантируется. Панель не регистрирует новые номера.

## Прогрев аккаунтов

На странице аккаунтов выбери не меньше двух готовых аккаунтов (без выбора используются все) и нажми «Прогреть аккаунты». В диалоге отредактируй сообщения: одна строка — один вариант. Каждое сообщение получает случайный текст и случайного получателя среди остальных участников этого же пользователя панели. Каждый аккаунт имеет свой интервал 40–80 минут, который заново выбирается после каждой отправки; первая отправка также через 40–80 минут. Отправка прекращается через 24 часа после запуска. Одновременно доступна одна задача на пользователя.

Применить новую схему базы: `.venv/bin/python manage.py migrate`. При запуске через `manage.py runserver 127.0.0.1:8000` исполнитель включается автоматически. Для WSGI/ASGI запусти отдельный процесс `.venv/bin/python manage.py run_warmups` на том же хосте с той же базой и `var/`. Блокировка допускает только одного исполнителя на хосте. Не запускай `run_warmups` при открытом `runserver`: у него уже есть исполнитель.

Расписание и счётчики хранятся в базе. Вкладку можно закрыть, сервер должен работать. После перезапуска отправка продолжается в пределах исходных суток; пропущенные интервалы не воспроизводятся пачкой. Запланированный слот фиксируется перед отправкой, поэтому при аварии во время запроса его повторной отправки не будет, а счётчик может не отразить сообщение, принятое Telegram. Ошибка отправки записывается для конкретного участника и в журнал, затем исполнитель переходит к следующему готовому по расписанию аккаунту. Повторная попытка — в новый интервал 40–80 минут; при FloodWait она откладывается как минимум на указанный Telegram срок. Если сессия занята редактированием профиля, отправка откладывается на новый интервал. Остановка ожидает завершения текущей операции и запрещает следующие сообщения. В панели отображаются состояние исполнителя, следующая отправка, счётчики ошибок и последняя ошибка каждого участника; в журнале — отправитель и получатель без текста сообщения.

Сообщения адресуются только выбранным аккаунтам владельца. Получатель определяется из сессии отправителя по актуальному username либо по номеру телефона, если Telegram разрешает поиск; ID проверяется перед отправкой. Недоступный получатель приводит к пропуску текущей отправки. Тексты из диалога сохраняются в базе. Этот режим не гарантирует изменение лимитов Telegram.

## Проверка сессий и спамблоков

В блоке «Здоровье аккаунтов» доступны «Проверить сессии» и «Проверить спамблоки»: проверяются выбранные в таблице аккаунты либо все, если выбора нет. Отдельные проверки также есть в меню строки и карточке аккаунта. Проверка сессии подтверждает авторизацию и совпадение Telegram ID с аккаунтом панели. Сетевая ошибка отображается отдельно от отозванной или повреждённой сессии.

Проверка спамблока сначала проверяет сессию, затем отправляет `/start` официальному @SpamBot и ожидает новый ответ. Известные ответы на русском и английском показывают отсутствие ограничений или спамблок; неизвестный текст отображается как «Не определено». Полный текст ответа (до 4096 символов), статус и время проверки сохраняются и доступны в карточке. Это снимок состояния на момент проверки. Ошибка или таймаут бота не означают отсутствие ограничений. FloodWait сохраняет время следующей разрешённой проверки и запрещает запросы до его наступления.

Проверки выполняются последовательно; ошибка одного аккаунта не мешает остальным. «Остановить после текущего» прекращает следующие проверки. Доступ ограничен владельцем и защищён CSRF, операции используют ту же блокировку сессии, что и прогрев. Проверки запускаются пользователем, автоматически @SpamBot не опрашивается. Новая схема: `.venv/bin/python manage.py migrate`. Тесты: `.venv/bin/python manage.py test accounts.test_checks accounts.test_warmup`; реальные аккаунты в них не используются.

## Индивидуальные жалобы

Открой карточку готового аккаунта и нажми «Подать жалобу». Выбери «Аккаунт или чат» либо «Сообщение», укажи username или прямую ссылку t.me. Для сообщения можно также указать username чата и ID сообщения. Ссылки на приватные сообщения каналов/групп поддерживаются только при доступе выбранного аккаунта к чату; ссылки вида `?comment=…` не поддерживаются.

Для аккаунта/чата выбери фактическую причину из списка и добавь пояснение до 1000 символов; для «Другое» оно обязательно. Для сообщения причины и уточнения возвращает Telegram, затем API может запросить обязательный или необязательный комментарий. Каждый запрос к API требует подтверждения в форме: выбор причины иногда сразу завершает подачу. В журнале успех отображается только после подтверждения приёма со стороны Telegram; решение модерации неизвестно.

Отправка использует только аккаунт открытой карточки. Черновик хранится зашифрованным и действует 15 минут. Завершённая попытка, ошибка или сбой во время запроса не воспроизводятся автоматически; при потере ответа жалоба могла быть принята. Применить миграцию: `.venv/bin/python manage.py migrate`. Автоматические тесты используют подмену Telegram и не отправляют реальные жалобы.

## Личные сообщения со всех аккаунтов

В окне «Сообщения / комментарии» есть режим «Личные сообщения пользователям», а в шапке таблицы — кнопка «В личку». Выбери отправителей или нажми «Выбрать всех», укажи от 1 до 10 получателей (@username, прямая ссылка t.me на пользователя или номер телефона с кодом страны) и общий текст до 4096 символов Telegram. Поиск по телефону выполняется через `contacts.resolvePhone` без добавления контакта и зависит от приватности получателя.

«Проверить и продолжить» создаёт предпросмотр: имена получателей, отправители, текст и общее число отправок. После подтверждения каждый выбранный готовый аккаунт отправляет каждому получателю одно личное сообщение от собственной сессии. Получатель заново определяется перед каждой отправкой и сверяется по Telegram ID с предпросмотром; смена владельца username не перенаправит сообщение. Боты, удалённые пользователи, чаты и каналы в этом режиме не принимаются.

Результаты сохраняются отдельно для каждой пары отправитель/получатель. Ошибка отправителя (включая FloodWait, PeerFlood, отозванную или занятую сессию, сетевой сбой и неизвестный результат) пропускает этот аккаунт и все его оставшиеся отправки, затем очередь продолжает работу с другими аккаунтами. Неизвестная попытка не повторяется. При потере HTTP-ответа панель отдельным запросом сохраняет пропуск, сохраняя подтверждённую отправку, если сервер успел её завершить. Смена Telegram ID получателя останавливает задачу, чтобы сообщение не ушло другому пользователю. «Остановить после текущего» пропускает все оставшиеся отправки. Повторный запрос уже обработанной отправки не создаёт новое сообщение. При отправке вкладка должна оставаться открытой. Новая миграция для этого режима не нужна; тесты: `.venv/bin/python manage.py test accounts.test_direct_messages` (без реальных сообщений).

## Сообщения и комментарии в своих чатах

В шапке списка аккаунтов нажми «Сообщения / комментарии». Выбери режим, аккаунт владельца Telegram-чатов/каналов и отправителей. По умолчанию используются выбранные в таблице готовые аккаунты, а если выбора нет — все готовые; в форме есть «Выбрать всех». Добавь до 10 ссылок, по одной на строку, и текст до 4096 символов Telegram. Поддерживаются до 100 отправителей и по одной отправке от каждого каждому адресату.

Нажми «Проверить и продолжить»: сервер проверит, что аккаунт владельца является создателем каждого указанного чата или канала в Telegram. Для комментариев нужен конкретный пост канала, включённое обсуждение и владение также связанной группой. Затем проверь названия адресатов, текст, список отправителей и число отправок; отметь подтверждение и нажми «Отправить». Перед каждой отправкой владение проверяется снова; изменение username, адресата или обсуждения не перенаправляет публикацию.

Для сообщений поддерживаются @username, прямые t.me-ссылки на чаты/каналы и приватные приглашения для уже вступивших аккаунтов. Для комментариев — t.me/channel/post, t.me/s/channel/post и t.me/c/channel_id/post. Вступление, назначение прав и оплата сообщений не автоматизируются. Отправителям нужны доступ к чату и права на публикацию; в каналах Telegram обычно требует права администратора. Текст отправляется без разметки и предпросмотра ссылок, от собственного имени аккаунта.

После подтверждения запросы выполняются последовательно без искусственных задержек. Не закрывай вкладку до завершения. «Остановить после текущего» прекращает следующие отправки; уже принятые сообщения остаются. Ошибка конкретного отправителя, включая FloodWait, SlowModeWait или потерю связи, пропускает его оставшиеся отправки и позволяет другим аккаунтам продолжить. Изменение адресата или обсуждения останавливает задачу. Результаты сохраняются в базе, текст и приватные ссылки — в зашифрованном черновике сроком на час. Уже отправленная или неопределённая попытка повторно не выполняется даже при повторном запросе. Успешные отправки попадают в журнал без текста сообщения.

Применить схему: `.venv/bin/python manage.py migrate`. Проверки публикаций: `.venv/bin/python manage.py test accounts.test_publications` — Telegram заменён управляемым клиентом, реальные сообщения не отправляются.

## Данные и сессии

Для локального запуска используется SQLite в `var/db.sqlite3`. Telegram-сессия StringSession и API-ключи зашифрованы Fernet. Ключ шифрования и ключ Django создаются один раз в `var/` с правами 0600; их можно задать переменными окружения. База, ключи, .env и .venv исключены из Git. Сохраняй резервную копию базы вместе с ключом шифрования: без него сессии восстановить нельзя. Коды и пароли 2FA не сохраняются.

Панель использует Django session cookie (HttpOnly), CSRF и ограничение доступа к собственным аккаунтам. Фото также доступны только владельцу. Каждая операция подключает сохранённую сессию и отключается в finally; файловая блокировка исключает параллельную работу с одной сессией между процессами на одном хосте. Не копируй эти сессии в другие приложения. Удаление из панели удаляет сохранённую сессию, но не удаляет Telegram-аккаунт и не отзывает её на стороне Telegram; отозвать устройство можно в Telegram → Настройки → Устройства.

Генерация выполняется локально в браузере: абстрактные JPEG-аватарки, случайные имена, username и описания. Одна кнопка готовит предпросмотр для всех или выбранных аккаунтов. Применение отправляет отдельные последовательные запросы, показывает частичные ошибки и приостанавливает оставшиеся при FloodWait. Уникальность username в Telegram окончательно определяется при сохранении. «Остановить» прекращает следующие запросы; текущий запрос завершается. Закрытие вкладки прерывает очередь, уже сохранённые изменения остаются. Неудачное частичное изменение не откатывает успешно применённые поля.

Это локальная конфигурация запуска. Для размещения на сервере используй HTTPS, COOKIE_SECURE=true, реальные ALLOWED_HOSTS/CSRF_TRUSTED_ORIGINS, DEBUG=false и WSGI-сервер. Несколько хостов требуют отдельного единственного владельца каждой Telegram-сессии и общего ограничения попыток входа. Для большого объёма аккаунтов потребуется PostgreSQL и очередь задач.

## Проверки

```bash
.venv/bin/python manage.py check
.venv/bin/python manage.py test accounts
```

Тесты проверяют права доступа, CSRF, шифрование, шаги входа с 2FA, истечение кода, блокировку одновременных операций, частичные ошибки профиля и проверку изображений. Telegram в автоматических тестах заменён управляемым клиентом: реальные аккаунты не изменяются.
